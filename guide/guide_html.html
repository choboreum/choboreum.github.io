표준 문법의 사용

  • HTML은 해당 DTD의 명세에 맞게 작성하며, W3C validation을 통과해야 한다.
  • DTD를 제외한 모든 엘리먼트와 속성은 소문자로 작성한다.
  • 속성의 값은 큰따옴표("")로 묶는다.
  • 특수기호는 Entity name을 사용하여 entity 코드로 변환한다. Entity 코드는 ISO-8859-1을 기준으로 한다.
  • 마크업은 w3c html5문법에 준하여 사용한다.
  • 종료 태그는 생략하지 않는다.

언어 / 문자셋(charset) 지정

  • lang 속성은 User Agent가 언어를 올바로 해석할 수 있게 도와주며, 검색과 음성 장치에 활용된다.
  • utf-8은 다국어 지원이 가능하며, euc-kr 보다 표현 가능한 한글(고어, 음절 등)이 많음.
  • 한글은 utf-8에서 3바이트, euc-kr에서 2바이트를 차지하기 때문에 utf-8이 euc-kr에 비하여 DB 저장 용량이나 트래픽이 많을수 있음.
  • utf-8 인코딩 기본. DB의 인코딩 방식과도 관련이 있으므로 개발자와 협의하여 결정.

Meta viewport 설정

뷰포트란 현재 화면에 보여지고 있는 여역을 의미한다, 기기별로 뷰포트가 다르기 때문에, 동일한 웹페이지라도 기기에 따른 배율 조정이 발생해 화면의 크기가 다르게 보이는 현상이 나타난다. 이러한 배율 문제에 대응하기 위해 meta 태그를 통해 뷰포트 관련 설정을 추가할 수 있다.

  <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, minimum-scale=1.0, user-scalable=no, target-densitydpi=medium-dpi">
  • width=device-width : 브라우저 너비를 장치 너비에 맞추어 표시
  • initial-scale=1.0 : 초기 화면 배율 설정, 1.0은 100%와 같음
  • maximum-scale=1.0 : 최대 화면 배율 설정
  • minimum-scale=1.0 : 최소 화면 배율 설정
  • user-scalable=no : 사용자가 브라우저의 확대축소를 가능하게 할 것인지 정의
  • target-densitydpi=medium-dpi : DPI 지정

구조, 표현, 동작의 분리

문서의 구조(HTML)와 표현(CSS), 동작(script) 언어를 본래의 목적에 맞게 최대한 분리한다.

예외사항

  <input type="text" id="formMyClass" class="my-class" style="width: 80%;" />
  • 특정 엘리먼트에 id, class, style을 선언할 때에 선언 순서는 엘리먼트의 기본 속성 지정후 마지막에 id, class와 style을 선언한다.
  • 테이블 셀의 경우 다양한 너비의 고정폭을 지닐 수 있는데 이것을 모두 CSS로 지정하는 것은 기대했던 효과에 대한 이점이 없으므로 예외의 경우를 허용함
  • 필요 시 input, select 엘리먼트의 경우 너비의 고정폭 지정 허용함

적절한 태그 및 속성 사용

  • 클릭했을 때 이벤트(function)가 발생하는 경우 <button> 태그를 사용한다.
  • 클릭했을 때 다른 페이지로 넘어가는 경우나 다운로드, 전화, 이메일 등의 경우 <a> 태그를 사용한다.
  • <a> 태그 안에 <button> 태그를 넣는 등 인터랙티브 요소에 인터랙티브 요소를 넣지 않도록 한다.
  • 단락이 아닌 경우, 단순히 block 속성을 사용하기 위해서 <p> 태그를 사용하지 않는다.
  • <heading> 태그는 레벨 순서를 지켜 작성한다.
  • <button> 태그에는 [type=""]을 명시한다.

엘리먼트의 기본 속성 및 지정 순서

  • User Interface 의 동작이 요구되면 id와 class속성을 선택적으로 사용할 수 있다.
  • id와 class 속성은 제일 뒷부분에 작성한다.
<a href="" target="_blank" title="새창" class="btn"></a>

section/article 태그 내에 제목 태그 필수 포함

  • <section> 태그와 <article> 태그는 독립적인 구획을 나타내는 데 사용한다.
  • 제목을 포함하고 있는 영역일 경우 제목 태그(<h1> ~ <h6>)를 포함시켜 웹 접근성 측면에서 각 구획을 식별할 수 있게 해야 한다. 
      <section>
    <h2>공지사항</h2>
  </section>
  • 디자인 시안에 제목 태그가 없는 경우에는 다음과 같은 class 사용을 통한 숨김 처리를 하여, 스크린 리더에서 인식이 가능하도록 한다. 
      <section>
    <h2 class="sr-only">공지사항</h2>
  </section>

  • 링크의 목표가 명확하지 않은 경우 title 속성의 값으로 부가적인 설명을 제공한다.
  • 새창열림 : [title="홈페이지명+새창으로 열기"]
  • 다운로드 : [title="파일명+파일확장자 다운로드"]

iframe

  <iframe src="about: blank;" title="빈프레임"></iframe>
  • <iframe> 사용은 페이지 성능에 영향을 주시 때문에 가급적 사용을 하지 않는다.
  • iframe은 가장 마지막으로 로딩되기 때문에 페이지 로딩 초기에는 화면이 비어 보일 수 있다.

img

  <img src="img.png" alt="대체텍스트" />
  • alt 속성은 반드시 제공되어야 하며 빈 값을 사용하지 않는다.
  • 아이콘, bg와 같이 의미가 없는 이미지에 대해서는 되도록 img태그가 아닌 가상선택자 after, before 를 사용한다.
  • 단, 의미없는 이미지에 대하여 가상선택자로 사용할 수 없이 img로 태그로 사용 되어야 하는 경우가 있다면 alt속성을 빈값으로 작성하며 aria-hidden="true" 속성을 필수로 기입한다.

코드 작성

들여쓰기

코드의 가독성을 높이고 전체 HTML 구조를 쉽게 파악하기 위하여 들여쓰기 규칙을 준수한다. 마크업의 중첩이 깊어질 때마다 자식 엘리먼트는 1탭 들여 쓰고, 1탭의 크기는 공백 4칸으로 설정한다.

들여쓰기를 하지 않는 경우

  <!DOCTYPE html>
  <html lang="ko">
  <head>

  </head>
  <body>
  <div id="wrap">

  </div>
  </body>
  </html>

들여쓰기를 한 경우

  <!DOCTYPE html>
  <html lang="ko">
    <head>
  
    </head>
    <body>
      <div id="wrap">

      </div>
    </body>
  </html>
  • html의 자식 엘리먼트인 head, body
  • body의 자식 첫 번째 엘리먼트 div="wrap"

빈줄 / 주석

  • 그룹을 감싸고 있는 객체를 구분하기 위개하여 코드 그룹 간 1줄씩 빈 줄을 만드는 것은 허용한다.
  • 빈 줄의 간격이 1줄을 초과하지 않으며 발과 연동되는 그룹의 경우는 빈줄보다 주석을 작성한다.
  • 코드의 가독성을 높이고 전체 HTML 구조를 쉽게 파악하기 위하여 주석사용을 준수한다.
  <!-- header -->
  <header id="header">
    <!-- logo -->
    <a href="" id="logo"> </a>
    <!-- //logo -->
  </header>
  <!-- //header -->

  <!-- container -->
  <div id="container">
  
  </div>
  <!-- //container -->

  <!-- footer -->
  <footer id="footer">
  
  </footer>
  <!-- //footer -->
  • 주석 기호와 주석 내용 사이에는 반드시 공백 한 칸이 있어야 한다.
  • 시작과 종료주석의 내용은 동일해야 한다.
  • 레이아웃 엘리먼트를 제외한 독립된 콘텐츠 영역의 주석 표기는 선택 사항이다.
  • 개발 적용과 관련된 주석은 해당되는 영역 라인 끝에 표기하며, 종료 주석은 표기하지 않는다. 주석 앞에는 [DEV]라는 말머리를 사용하여 담당 개발자가 반드시 확인할 수 있도록 한다.
  <!-- modal-popup -->
  <div class="modal-popup"> <!-- [DEV] : 241206 | 활성화 시 addClass="active" 필요 -->
    <p class="title type1"> <!-- [PUB] : 241206 | css 우선순위를 위해 class="type1" 추가 -->
    
    </p>
  </div>
  <!-- //modal-popup -->
  • "[주석 확인 대상자] : 작성일 | 코멘트" 순으로 작성한다.
  • [DEV] : 개발자를 위한 주석, 개발에 넘겨야 할 내용을 상세히 작성한다. 종료 주석은 표기하지 않는다.
  • [PUB] : 퍼블리셔를 위한 주석, 마크업 작업 시 특이사항을 작성한다.

아이디(id)

ID는 개발을 위해서만 사용하고, 퍼블리싱 작업시에는 앵커 및 label 등의 연결하는 상황 등을 제외하고는 일반적으로 사용하지 않으므로 정리하여 기재하지 않는다.

아이디 네이밍 규칙 예

아이디 네이밍 규칙 예
잘못된 예 올바른 예
error_Mesage errorMesage
control-center controlCenter
  • 시작의 이름은 영문 소문자를 사용하되 두 번째 단어부터 첫 번째 문자를 대문자로 처리하는 기법(카멜 케이스)을 사용한다.
  • 동일한 이름의 id는 문서에서 한번만 사용이 가능하다.
  • 지정된 레이아웃 및 폼객체를 제외한 스타일 지정을 위하여 id를 사용하지 않는다.
  • 앵커로서 사용되는 엘리먼트는 id 지정이 가능하다.
  • User Interface 동작을 위하여 DOM 선택자로서의 id 지정은 가능하다.

class 네이밍 확장

종속 확장

기본형 class에 종속되어 여백, 색깔, 행간 등의 몇 가지 속성을 부여하고자 할 때 사용하는 class. 다음은 input_wrap class 확장 예시이다.

<div class="input-wrap type1"></div>
<div class="input-wrap type2"></div>

독립 확장

기본형 class의 변형이 type으로 분류할 만큼 클 경우 사용하는 class로, 작성 예시는 다음과 같다.

  <div class="input-wrap-a"></div>
  <div class="input-wrap-b"></div>
